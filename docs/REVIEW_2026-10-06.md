# CodeSage: independent check, test and rating (2026-10-06)

**Overall: 6.5 / 10 as reviewed; 7 / 10 after the same-day fixes (section 11); 7.5 / 10 after the first real answers,
from a local model run offline (section 12).** The default provider, Claude, has still never been sent a request.

**Overall as reviewed: 6.5 / 10.**

It is a carefully engineered, honestly documented **code search engine** with an **answer generator that has never been
run**. Everything that could be tested without a language model held up: 960 tests, green CI, hardened inputs, and
retrieval that stayed strong on two libraries it had never seen. The thing the project promises, answers that explain
code with checked citations, has **still never been observed once**. A Q&A tool that has never answered a question
cannot score higher than this, however good the plumbing is.

**Conflict of interest:** this review was done by the same AI assistant that wrote the code. To counter that, the
retrieval test used questions written blind on two libraries the system was never evaluated on, labels were fixed
before running, and the security checks were adversarial. An outside reviewer would still be better.

## 2. Blind retrieval test on code it had never seen

Questions were written in plain English, avoiding the code's own names where possible (for example "return canned
responses without real network requests" for `MockTransport`). Every label was checked to exist before indexing.
**The one fix after the first run:** the labels used `httpx/_client.py` while the index stores paths relative to the
indexed folder (`_client.py`). The tool warned about it immediately ("16 labelled files are not in the index"), and
only the prefix was changed.

| Repository | Files / chunks | Index time (CPU) | Config | Hit@1 | Hit@3 | Hit@5 | MRR | Gold symbol in context |
|---|---|---|---|---|---|---|---|---|
| `httpx` | 23 / 433 | 73 s | **vector** (default) | 89% | 94% | 94% | **0.915** | 100% |
| | | | keyword | 72% | 94% | 94% | 0.824 | 94% |
| | | | hybrid | 78% | 94% | 94% | 0.861 | 100% |
| `jinja2` | 25 / 696 | 89 s | **vector** (default) | 67% | 94% | 100% | **0.801** | 83% |
| | | | keyword | 61% | 78% | 94% | 0.721 | 72% |
| | | | hybrid | 67% | 89% | 100% | 0.806 | 72% |

- **Pooled, 36 questions, default config:** Hit@1 78%, Hit@5 97%, MRR 0.858. A gold file was in the context sent to the
  model for **100%** of questions in both repositories.
- **The published findings replicate:** vector beats keyword, and hybrid adds nothing measurable.
- **Identifier lookups** (bare names such as `select_autoescape`): vector MRR 0.923 (`httpx`) and 1.000 (`jinja2`).
- **The one miss:** "Which class lets me return canned responses without making real network requests?" never
  surfaced `_transports/mock.py` in the top 5; meaning-based search did not connect "canned" with "mock".
- **Hit@1 is the soft spot:** on `jinja2` the right file is first only 2 times in 3. A model still sees it (it is in
  context every time), but "the first result is the answer" is not reliable.
- **Caveat:** these are two small, well-named Python libraries, the easy case. Real applications are messier
  (section 3).

## 3. Real-world drift: MagnaFlow, grown 74%

MagnaFlow went from 169 files and 1,184 chunks (September labels) to **294 files and 1,903 chunks**.

| Measure | September | Today |
|---|---|---|
| Index time, first run | not recorded at this size | **236 s** (about 8 chunks per second on CPU) |
| Re-run, nothing changed | | **13 s** |
| Hit@1 / Hit@5 / MRR (vector + test demotion) | 72% / 100% / 0.818 | 64% / **97%** / **0.772** |
| Keyword-only MRR | 0.634 | 0.638 |

The drop is graceful and partly label staleness. The one miss (q11, "which tasks can a department head or manager
see?") now retrieves `src/lib/taskPermissions.js`, a file added after the labels were written, and arguably a correct

**What the index report showed on a real repository (good):** `.env.emulated` skipped as a secret file; `node_modules`,
`dist`, `.git`, `backups` and lockfiles skipped; two files with key-shaped strings skipped (see section 9). Every skip
is listed with its reason.

**What it also showed (a bug):** `CLAUDE.md`, the single best overview document in the repository, was **dropped as
"minified_or_generated"** (section 6, bug 1).

## 4. Answer pipeline and citation checker (stand-in model)

The real index and embedding model were used; the language model was replaced by a stand-in that records its prompt.

- **A normal question** ("How does the client follow redirects...?") produced 17 numbered sources (about 20,000
  characters, about 5,000 tokens), led by the redirect code in `_client.py`, with class headers attached.
- **An overview question** ("What does this project do and how is it organised?") was recognised and got the generated
  repository map as source [1]. On `httpx` the map is useful (directories, what `_transports/` defines, files that
  describe themselves), but the other retrieved sources were weak: one was a three-line type alias from `_main.py`.

**Citation checker, fed deliberately bad output:**

| Trap in the model's answer | Expected | Result |
|---|---|---|
| `[42]` when only 17 sources exist | removed and reported | ✅ removed, reported as invalid |
| `[2][3]` chained | two valid citations | ✅ |
| `[Source 1]` | a valid citation | ✅ |
| `httpx/_secret_module.py:10-20` (file never shown) | flagged | ✅ unverified location |
| `_client.py:99999-100000` (lines never shown) | flagged | ✅ unverified location |
| `` `items[1]` `` in a code span, `matrix[1][2]` in prose | ignored | ✅ ignored |

Cosmetic: removing `[42]` leaves the sentence ending "...and in." The text is not repaired.

**What this does not show:** whether a real model's answer is right. The checker proves a citation points at code that
was supplied, not that the code says what the sentence claims. That needs the never-run faithfulness evaluation.

## 6. Bugs and defects found today

Ranked by impact. Status after the follow-up is in section 11: 1, 2 and 5 to 10 are fixed; 3 and 4 were measured and
left alone.

1. **Markdown files with one long line are silently dropped.** `ingest/walker.py:117` skips any file with a line
   over 2,000 characters as "minified". Markdown is often written one paragraph per line, and MagnaFlow's `CLAUDE.md`
   (one line of 2,056 characters) was excluded. This hits the overview feature hardest, because it depends on exactly
   such documents. The skip is listed in the index report, but nobody reads that. **Fix:** apply the rule to code only
   (one condition).
2. **`search` does not show what `ask` sends for overview questions.** The repository map is added only in the answer
   path, so the tool you would use to debug "why did it answer that?" shows a different context. **Fix:** route
   `search` through the same retriever wrapper.
3. **Prose can still outrank code** (known, documented): on `psf/requests` the changelog ranked above the redirect code.
4. **Vague questions pull junk chunks.** For the overview question, a three-line type alias ranked third. Very short
   chunks match vague queries too easily.
5. **Model-loading progress bars leak into CLI output** ("Loading weights: 100%|████|") on `ask`, `search` and `eval`.
6. **Indexing an empty or wrong folder reports success.** It loads the model (17 s) and reports 0 files with no
   warning.
7. **"Fetching ... (shallow clone)..." is printed before the branch name is validated**, so a refused branch looks
   like it started a download. Nothing is actually run.
8. **Removing an invalid citation leaves broken prose** ("...and in.").
9. **Streamlit's own "Deploy" button and promotional toast** show in a tool meant to run locally (one config line hides
   them).
10. **One documentation figure is stale:** `docs/ARCHITECTURE.md` section 7 says map coverage rose "to 90%"; the
    current figure in the evaluation documents is 93%.

**Overall 6.5 / 10.** The overall score is a judgement, not an average: one unproven core feature outweighs several
strong supporting ones. As a **portfolio or learning project** it is a solid 8: it shows engineering judgement, testing
and intellectual honesty that most RAG demos lack. As a **product someone could rely on today** it is a 5: they would be
the first person ever to read its answers.

## 8. What would move the score, in order

1. **Run it once with a real model** (an API key, or Ollama with a code model) on about 20 labelled questions, grade the
   answers by hand, and record the faithfulness numbers (`eval/run_answers.py` exists for this). If the answers are
   good, this alone is worth +1 to +1.5. If they are bad, it is the most important thing to find out.
2. **Fix the Markdown drop** (one condition in `walker.py`), then re-run the overview evaluation.
3. **Make `search` show exactly what `ask` would send**, including the map.
4. **Get 30 to 50 questions written by someone else**, on repositories they know. Until then every number is
   self-graded.
5. Polish: silence the progress bars, warn on an empty index, hide Streamlit's deploy chrome, repair prose after
   removing a citation, update the stale 90% figure.

## 9. Side finding in MagnaFlow (not CodeSage)

CodeSage's secret filter flagged a Google API key hard-coded in two tracked MagnaFlow files:
`scripts/admin/cleanup-duplicate-designations.mjs` (line 6) and `scripts/admin/create-fresh-admin.mjs` (line 7).
Firebase web API keys are public by design (they ship in the browser bundle), so this is probably harmless. Still,
confirm it is the web key and not a server key, and consider reading it from the environment like the other scripts.
The value was not printed or copied anywhere.

## 10. Limits of this review

- **No language model was available**, so the most important property, answer quality, was not tested.
- **The blind questions were written by the same AI that built the system.** They target libraries it was never tuned
  on, but they are not independent of its way of phrasing things.
- **Single runs on one machine** (AMD Ryzen 5 5600H, 15 GB RAM, CPU only, Windows 11).
- **Not re-tested today:** cloning a git URL for real (verified on `psf/requests` on 2026-10-01), Java and Go chunking
  on real code (only a small fixture), and repositories larger than about 300 files.

## 12. The first real answers (offline, same day)

With the owner's go-ahead, Ollama 0.35.1, `qwen2.5-coder:7b` (answers) and `gemma3:4b` (judge) were installed and the
answer-quality evaluation was run on this laptop with nothing sent anywhere: 30 answers in all (`QUALITY_EVAL.md`
section 3 has every number).

| Finding | Evidence |
|---|---|
| Citations are never invented | validity 100% and no made-up location in 30 answers |
| A third of the answers cited nothing at first | grounded 65% on the first 20; the model named files in prose |
| **Fixed by a one-line reminder at the end of the prompt** | 10 held-out `jinja2` questions: grounded 40% to 100%, gold file cited 30% to 100%, better on 6 and worse on 0 (p = 0.03); correctness unchanged (8 vs 7 fully correct) |
| Answers are mostly right | hand-graded against the code: 14 of 20 correct, 4 partly, 2 wrong |
| Faithful is not correct | both wrong answers describe the code they cite accurately: retrieval supplied a highlighting function and an undeployed Cloud Function |
| The 4B judge is useless | it called all 33 answers it judged "supported"; no faithfulness number is quoted |
| Real demo | the README now shows a real `ask` answer, including a citation (`[15]`, a test) that does not support its sentence |

Using the system for real also found three more defects, all fixed with tests: the hand-check file did not show the
cited code (so it could not be graded), the run's plan promised 16,000 output tokens from a provider that caps at
4,096, and the default 120 s model timeout is tight for a laptop (documented; the run used 600 s). **980 tests pass.**
