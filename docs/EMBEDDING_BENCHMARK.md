# Embedding model benchmark (M1)

Run on 2026-09-29 · Windows-11-10.0.26200-SP0 · CPU only. Generated by `eval/bench_embeddings.py`; raw per-question results are in `eval/results/embedding_bench.json` (not committed).

## Setup

- **Target repo:** `MagnaFlow` — 169 indexable files, 1184 chunks (React/JavaScript app plus docs, Firestore rules and scripts).
- **Questions:** 36 hand-written natural-language questions, each with 1–3 gold files (4 doc, 22 explain, 10 locate).
- **Metric:** chunks are ranked by similarity, collapsed to a ranked list of *files*, and scored on where the first gold file lands. `Hit@k` = share of questions with a gold file in the top k files; `MRR` = mean reciprocal rank (cut at 10).
- **Retrieval:** vector search only, top 40 chunks per query. Hybrid search and reranking are M2.
- **Candidates:** general-purpose sentence-embedding models that load *without* `trust_remote_code`. Code-specific embedding models were excluded because the ones considered require executing code shipped with the model download.

## Reading the numbers

_This section is written by hand; `bench_embeddings.py` keeps it when it regenerates the tables above._

**Decision: keep `BAAI/bge-small-en-v1.5` as the local default** (`LOCAL_EMBEDDING_MODEL`). It scored best on every measure, indexes 2.7x faster than `bge-base` (211 s vs 561 s on this CPU) and its vectors are half the size (384 vs 768 dimensions).

**What the data supports**

- **Embeddings clearly beat keyword-only search** on this repo: MRR 0.70–0.81 vs 0.63, Hit@5 89–100% vs 78%. Question by question, `bge-small` ranked the right file strictly higher than BM25 on 14 questions, lower on 4, and equal on 18.
- **Bigger did not help.** `bge-base` (110M parameters) was no better than `bge-small` (33M): 94% vs 100% Hit@5 is a two-question difference.
- **`Snowflake/snowflake-arctic-embed-s` is the weakest at putting the right file first** (Hit@1 53% vs 67–72% for the others).
- **`all-MiniLM-L6-v2` is a reasonable fast fallback:** 3.4x quicker to index than `bge-small` and only 0.05 MRR behind, even though it truncates each chunk at 256 tokens instead of 512.

**What it does not support (36 questions is small)**

One question is worth 2.8 percentage points, so the differences among the top four models (`bge-small`, `bge-base`, `e5-small`, `MiniLM`) are within noise. The data says "the small BGE model is at least as good as the alternatives here and cheaper", not "it is the best model".

**Limits of this benchmark**

- **One repository** (React/JavaScript app plus Markdown docs, Firestore rules and shell/Node scripts). No Python, Java or Go repository was tested.
- **Gold labels name code files only, but the index also contains prose that answers the same questions** (`CLAUDE.md`, `MAGNAFLOW_EXPLAINED.md`, `docs/`). Of the six questions where no model puts a gold file first, at least three (q06, q22, q29) have such an overview document in first place, which is a legitimate answer, so Hit@1 here understates real quality. Labels were deliberately *not* edited after seeing results. M2's eval set should distinguish `gold_files` from `acceptable_files` (docs that also answer the question).
- **The questions were written by the person building the system**, who had read the repo's overview documents, not by an independent developer.
- **Vector search only.** Even a perfect combination of keyword and vector results would lift Hit@1 from 72% to only 78% on this set (best-of-both per question), so hybrid fusion alone will help modestly here. Reranking and better chunking are the other levers, and M2 should measure each.
- **General-purpose models only.** Code-specific embedding models were excluded because the ones considered need `trust_remote_code` (they execute code shipped with the download). This could be revisited as an explicit opt-in.
- **CPU timings on one machine**, run once; index times include model warm-up.
